# 支付页面识别

在「设置 → 自动记账」开启「识别商户并补全记账」，通过按钮前往系统开启「Sextant 支付页面识别」无障碍服务，并启用自动记账、保存设置。页面读取和通知读取可以分别授权，微信、支付宝沿用现有来源开关。

当前页面适配器识别已完成的人民币消费，提取商户、实付金额、交易时间和平台交易单号。微信侧同时覆盖原生支付结果页与小程序支付结果页（`WxaLiteAppTransparentLiteUI`）：两者都只暴露「成功、商户、金额」加一个结束动作，区别是原生页以「完成」结束、小程序页以「返回商家」结束，结束动作用来确认这确实是一张结果页，不会被当成商户名。支付结果页没有时间时使用捕获时间；账单详情必须提供完整交易时间，避免将历史账单记到今天。详情页的商户名两个平台写法不同：原生页写在金额上方的标题里，微信在小程序里的支付卡片写在金额下面那行，两处都会尝试，但标题和字段名不会被当成商户。微信 WebView 交易详情页（`MMWebViewUI`）不暴露任何标题文本，改用卡片自己的字段名（`当前状态`/`收单机构`/`商户简称`/`商户单号`）确认这是详情卡，商户名也可以直接取「商户简称」字段；这类页面同样必须给出完整交易时间。转账、退款、红包、还款等仍走已有通知解析。识别依赖应用暴露的无障碍文本，并非所有版本或页面都支持。

解析在本机完成；只将提取的交易字段交给加密事件队列，不保存原始页面，不截屏、不点击、不上传。默认关闭，关闭总开关、页面开关或对应来源后均停止处理；系统授权可以随时撤销。

平台交易单号优先去重。没有单号时，只在同一平台、同金额、同方向、同交易类型、90 秒内寻找兼容的跨来源记录。存在多个候选，或同一来源已经匹配过而无法证明是同一笔时，保留失败事件并提示人工检查。该时间匹配仍属于启发式：极短时间内的相同金额消费可能无法区分，不能承诺绝对去重。

匹配到已有流水时仅补齐未被用户编辑的空白备注，不改金额、分类和用户备注；补全后刷新结果通知的撤销版本。页面生成的流水保存独立的 accessibility 来源，支持备份恢复及安全撤销。没有结构性数据库变更。

验证包括两平台文本样例、历史日期、模糊金额、非交易页面、通知与页面先后到达、重复捕获、用户编辑、撤销、交易单号冲突与备份来源。文本样例是合成测试数据；发布前仍需在真实微信、支付宝版本上核对节点结构，并验证支付结果页、历史详情页及连续同金额消费。
